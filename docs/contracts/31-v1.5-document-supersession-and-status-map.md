# Contract 31 — v1.5 Document Supersession and Status Map

Version: `1.5.0`
Status: `NORMATIVE CANDIDATE / HUMAN APPROVAL REQUIRED`
Goal ID: `AXIGNAL-GOAL-001`
Governing contract: `31`
Decision: `ADR-016`

## 1. Purpose

This map defines how every existing contract and principal roadmap document must be interpreted after Contract 31.

It prevents three errors:

1. rewriting historical evidence as though it were always v1.5-native;
2. allowing stale subordinate text to override Contract 31;
3. treating an unchanged document as silently accepted, rejected or irrelevant.

## 2. Interpretation classes

| Class | Meaning |
|---|---|
| `ACTIVE_UPDATED` | Directly updated for v1.5 and subordinate to Contract 31 |
| `ACTIVE_COMPATIBLE` | Remains applicable without a material v1.5 conflict |
| `ACTIVE_WITH_SUPERSEDED_SECTIONS` | Remains applicable except for sections explicitly overridden by Contract 31 |
| `PRESERVED_HISTORY` | Must remain unchanged as historical authority or evidence |
| `ENGINEERING_EVIDENCE` | Exact implementation evidence; not canonical acceptance |
| `NON_NORMATIVE_RESEARCH` | Research evidence only |
| `REQUIRES_FUTURE_UPDATE` | Must be revised by a later task before canonical acceptance |

## 12. Change rule

A future document conflicts with Contract 31 when it:

- treats P24 as final launch authority;
- permits partial public launch;
- conflates engineering and canonical state;
- treats historical prices as current;
- treats TED as AXIGNAL identity;
- treats a DNS token as API admission;
- treats MCP discovery as connection authority;
- treats P26-T01 as complete Founder Operations;
- enables signup, indexing, billing or launch without P27.

Such a document is blocked until corrected or explicitly superseded.
