# P17 — Cross-Library Intelligence

## Task

`AX-GE2E-P17-T01`

## Status

`ENGINEERING EVIDENCE READY` is distinct from canonical acceptance. P17 composes the
nine P08–P16 engineering runtimes only as tenant-scoped candidate/proposal projections.
No dependency is represented as product-admitted or canonically active.

## Objective

Connect bounded library projections across **Globe**, **Graph**, **Timeline** and
**Navigator** without authority contamination.

## Composition boundary

```text
engineering runtime present != product-admitted library
candidate entity link       != canonical identity
candidate graph edge         != canonical relationship
timeline alignment           != causal conclusion
map location                 != legal applicability
Navigator query plan         != source admission
projection READY             != external-action authority
```

Canonical composition requires source-specific admission and canonical activation for
every participating dependency. While that condition is false, P17 remains
`ENGINEERING_CANDIDATE_ONLY`.

## Surfaces

### Globe

Projects versioned spatial and jurisdictional anchors. It preserves disputed boundaries,
place-of-performance, asset location, market scope and cross-border applicability as
distinct concepts.

### Graph

Projects evidence-backed cross-library edge candidates. Every edge carries source
library, source record/version, evidence, rights, authority, tenant and temporal
envelopes. Contradictory edges coexist until reviewed.

### Timeline

Projects event, validity, publication, revision, vintage and recording axes without
collapsing them. Missing time is never replaced by `now`, and revision lineage is
append-only.

### Navigator

Accepts only server-resolved tenant/workspace scope. Models may propose bounded
cross-library query plans, but cannot widen sources, tenants, permissions or canonical
authority. Results return to `InvestigationContext` as facts, calculations, inferences,
unknowns and contradictions.

## Authority propagation

The composed object receives the least authority of its dependencies. Authority cannot
be averaged, voted or promoted by model confidence. Revoked or rights-denied inputs
contribute zero future authority.

```text
browser                    request only
connector/parser           candidate only
model                      proposal only
worker                     bounded mutation only
surface projection         candidate/proposal only
human reviewer             review only
typed human approver       exact scoped approval
independent admission      deterministic canonical write after approval
```

P17 has no external-action path. Contact, submission, signature, spend, publication,
export or representation remains in a separately typed human-authority workflow.

## Evidence and contradiction policy

Each projection requires tenant, workspace, source library, source record/version,
evidence, rights snapshot, authority, valid time, recorded time and projection identity.
Contradictions are first-class records. Unknown, unavailable, suppressed and zero remain
distinct. Translation and calculations never replace source-native evidence.

## Canonical gate

Canonical activation remains blocked until P08–P16 are admitted or superseded by a
normative ADR, transitive P01–P07 dependencies are resolved, all rights and privacy gates
are current, surface and isolation tests pass, rollback passes, and typed Human Data,
Security, Rights and Product Authorities approve.

## CI composition

The shared `Contract Validation` workflow remains byte-identical to P16. Its P16 rollback step is made forward-compatible by a scoped wrapper that rehearses the original verifier at the frozen P16 head, then validates
the complete P01–P16 stack plus every JSON Schema on the P17 head. The dedicated P17
workflow validates the P17 runtime, exact dependency bindings, deterministic functions,
fixtures, adversarial cases and rollback. This avoids mutating shared CI solely to
register a phase-specific verifier while preserving exact-head cumulative evidence.
